The loop

Observe, cast, understand, return.

Observe→Form a hypothesis→Cast an element or combination→Read the result→Record knowledge→Use the new option→Revisit a changed region

Knowledge, recorded in a field journal, is the main progression. A discovered rule opens a route, a build site or a way to survive.

Seven pillars

GDD 2.1 · the last one is new
PIL-1

Causal world

Actions produce readable, explainable effects.

Avoid Random effects that cannot be understood or repeated.

PIL-2

Experimentation

Players test ideas, observe results, revise hypotheses.

Avoid One correct recipe per problem; punishing early experiments.

PIL-3

Ecological memory

A region responds to accumulated changes over time.

Avoid Cosmetic-only persistence.

PIL-4

Knowledge is power

Discovery creates options beyond stat increases.

Avoid Progression dominated by repetitive XP grinding.

PIL-5

Useful construction

Structures manage resources, shelter, access and environment.

Avoid Decorative building disconnected from gameplay.

PIL-6

Scope-conscious simulation

Systems interact while staying performant.

Avoid Simulating every leaf, droplet or creature continuously.

PIL-7

Cinematic spellcraft (new)

Every elemental action is a performance: anticipation, release, impact, aftermath.

Avoid Spectacle that hides the rule, or flashy effects with no lasting consequence.

Elements / 01

Four forces.
One shared rulebook.

Elements act on tagged targets through deterministic rules. They are not four spell trees.

Fire

Verbs
Ignite, heat, dry, cook, transform
Targets
Combustible material, heat-sensitive resources, creatures
Trade-offs
Spread, smoke, resource loss, heat exposure

Water

Verbs
Wet, cool, pool, redirect, nourish
Targets
Ground, plants, heat, channels, materials
Trade-offs
Mud, erosion, flooding, reduced fire effectiveness

Earth

Verbs
Raise, block, stabilize, expose, shape
Targets
Soil, loose deposits, barriers, foundations
Trade-offs
Blocked routes, unstable cuts, cost, redirected water

Air

Verbs
Push, ventilate, disperse, dry, lift
Targets
Smoke, mist, particles, light objects, thermal zones
Trade-offs
Fire/spore spread, dust, loss of control in strong wind

From input to consequence

GDD 3.3 · an action has two layers
  1. 01

    Select

    State

    Show selected element and availability.

  2. 02

    Charge

    Cast

    Optional hold. Anticipation animation, camera shift, charging VFX/audio.

  3. 03

    Target

    State

    Trace/query finds an eligible target within range and line of sight.

  4. 04

    Validate

    State

    Check target tags, state, cost, cooldown and resistance. A failed check explains why.

  5. 05

    Release

    Cast

    Release animation, projectile or field, impact.

  6. 06

    Resolve

    State

    Apply deterministic state changes and emit an interaction event.

  7. 07

    Feedback

    Both

    Persistent cue (material, mesh, sound) plus the transient cue.

  8. 08

    Record

    State

    Novel or useful results add journal observations or confirmed rules.

A cancelled charge must clean up the cast layer and must not change state.

When rules collide

  • Safety-critical changes resolve before cosmetic effects.
  • Each target has one authoritative state per state family; overlap follows a declared priority.
  • Effects stack only when explicitly allowed; otherwise refresh duration or apply the stronger value.
  • Clamp values and use cooldowns to prevent runaway feedback loops.
  • In development builds, every rule logs: target, rule ID, preconditions, before/after state and rejection reason.

State transitions · GDD 4.5

Stages, not numbers.

Healthy→Stressed→Dormant/Damaged→Recovering→Healthy

Discrete tiers are cheaper, easier to debug and easier for players to read than a unique state for every value.

Ecological memory · GDD 4.4

What the world keeps.

  • Repeated overharvesting lowers local vegetation health and increases recovery time.
  • Water diversion changes moisture distribution; one route may green while another dries.
  • A burned patch follows a recovery stage rather than snapping back to baseline.
  • Creature territory suitability changes when water or food patches change.

How often things update

GDD 4.3
TierUpdatesNotes
ImmediateElemental hits, ignition, splashes, local state change, feedbackEvent-driven
Short-rangeNearby cells and active organisms on a timed cadenceTarget 1–5 updates/second for relevant actors; profile
RegionalDistant vegetation, populations, recoveryBatched
DormantUnloaded regions store summary stateBounded catch-up rules on revisit/load

Use authored presets: Calm, Windy, Rainfall, Dry Heat. They make bounded changes to airflow, moisture and temperature. Water movement uses simplified flow links/channels and cell-to-cell transfer, not computational fluid dynamics. Large-scale real-time landscape sculpting is out of scope; earth actions modify authored terrain or place discrete earthworks.

Habitat suitability

A weighted score from food, moisture, temperature, disturbance and safe cover. Prototype scoring is simple and deterministic. Thresholds change behavior; machine learning is not required.

Spectacle / 01

Power you can
read.

Action-fantasy weight on the outside, a legible simulation underneath. The two never trade places.

The spectacle contract · GDD 2.2

Five rules.

  1. The cast layer is allowed to be as cinematic as the budget permits.
  2. The cast layer reads from the state layer and requests changes through the rule resolver. It never mutates world state itself.
  3. Every meaningful result must also be readable after the effect ends, via a material change, mesh state, sound or journal entry (see 5.4).
  4. Disabling all VFX must leave gameplay state identical (test in Appendix A.2).
  5. A spectacle feature may not be accepted if a tester cannot say what it did.

Feedback stack · GDD 5.4

Two signals, one that persists.

Every meaningful elemental result combines at least two signals: visible world change, an audio cue, a concise UI message, a journal update or a clear animation. High-value discoveries deserve stronger feedback than routine updates. At least one of the signals must persist after the transient cue ends.

Legibility · GDD 5.5

Beauty never hides the rule.

A readable change is worth more than a beautiful ambiguous effect. Spectacle is welcome, but a simple mesh state change, clear sound and visible moisture/temperature cue must exist underneath it. If a tester cannot tell what a flashy effect did, the effect fails acceptance.

Playtest questions

  • Can a first-time player discover a useful interaction without the exact recipe being explained?
  • Can the player explain why the outcome occurred?
  • Does the result create a new option, problem or discovery?
  • Does the world appear to remember what happened after leaving and returning?
  • Do players naturally try multiple experiments?
  • Does survival support the elemental loop or distract from it?
  • Do testers describe the game as an elemental ecosystem sandbox rather than a conventional survival game?
  • Does the cast feel powerful, and can the player still say what it did? (new)

Definition of done

  • Feature has a written purpose and bounded scope.
  • Normal case and at least two failure cases are tested.
  • Result is readable to the player.
  • Feature survives save/load if intended to persist.
  • No known severe performance/stability issue in the test map.
  • Project is committed and can reopen from the repository.
